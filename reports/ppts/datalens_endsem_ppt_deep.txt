SLIDE 3  ·  INTRODUCTION
────────────────────────────────────────────────────────────────────────────────

What DataLens AI is.

  •  Offline-first dataset analyser. Takes any CSV / TSV / Excel / JSON,
     returns a structured, evidence-backed report.

  •  Six-phase pipeline: ingest → quality → parallel analytics →
     ML chain → reporting → agentic Q&A.

  •  Two surfaces: a 17-tab React dashboard at :5173 and a Streamlit
     visual console at :8501.

  •  All ML and statistics run locally on numpy / pandas / scipy /
     scikit-learn / statsmodels / xgboost / lightgbm / shap / pyod.
     LLM responses use Ollama (local or cloud) with TF-IDF + heuristic
     fallback.

  •  Defining property: every claim traces to a named algorithm, a
     concrete numeric output, and a bounded compute path.

  •  No "black-box magic" — the report shows which test was run, the
     statistic and p-value, what the cut-off is, and what the verdict
     means in plain English.


────────────────────────────────────────────────────────────────────────────────
SLIDE 4  ·  PROBLEM STATEMENT
────────────────────────────────────────────────────────────────────────────────

The gap.

  •  Profiling tools (ydata, pandas-profiling) cover stats but stop short
     of ML, drift, and SHAP.

  •  Drift tools (Evidently) require an already-modelled dataset.

  •  AutoML platforms model but do not profile or explain.

  •  LLM dataset assistants need cloud APIs and produce ungrounded text.

  •  Real-world CSVs are messy: encoding mismatches, mixed dtypes,
     irregular timestamps, ID-like columns that look numeric.

  •  Goal — one offline pipeline that does all of the above honestly,
     with every claim traceable to math.

SLIDE 5  ·  LITERATURE REVIEW
────────────────────────────────────────────────────────────────────────────────

Five families of prior work DataLens AI builds on.

  1.  Automated profiling — ydata-profiling / pandas-profiling, Sweetviz,
      AutoViz. One-shot HTML reports of dtypes, missingness, correlations
      and distributions. Strong on description, silent on modelling.

  2.  Drift & monitoring — Evidently AI, NannyML, WhyLabs. Implement PSI,
      KS, Wasserstein and chi-square between reference / current windows.
      Assume the dataset is already modelled and a baseline exists.

  3.  AutoML & explainability — auto-sklearn, H2O.ai, PyCaret, FLAML;
      SHAP (Lundberg & Lee 2017); LIME (Ribeiro 2016); permutation
      importance (Breiman 2001). Strong leaderboards and attributions,
      but treat the input table as already clean.

  4.  Anomaly detection & statistical testing — Isolation Forest (Liu,
      Ting, Zhou 2008), LOF (Breunig et al. 2000), robust covariance
      (Rousseeuw 1984), MAD-based z-scores (Leys et al. 2013). Time-series
      testing — ADF (Dickey & Fuller 1979), KPSS (Kwiatkowski et al. 1992),
      STL (Cleveland et al. 1990), Holt-Winters (Hyndman & Athanasopoulos
      2018). Each is well-studied in isolation; no public tool fuses them
      into one report.

  5.  LLM dataset assistants — ChatGPT Code Interpreter, Julius AI, Sketch,
      PandasAI. Conversational and powerful, but cloud-only and
      ungrounded — answers are generated text rather than traced to a
      named algorithm and a numeric result.

Takeaway — each family solves one slice. DataLens AI integrates all
five behind a single offline pipeline where every claim is anchored
to a formula.

SLIDE 8  ·  SYSTEM ARCHITECTURE
────────────────────────────────────────────────────────────────────────────────

Six-phase pipeline · 40+ modules · parallel where safe.

    [ React Dashboard ] ─ Vite · Tailwind · Highcharts
              │ JSON
    [ Flask API :5055 ]
              │
    [ run_full_analysis ] ─ modules/pipeline.py

    P1 Ingest       →  load → profile → roles → signals → selector
    P2 Quality      →  health → ml_readiness → advanced
    P3 Parallel     →  deep_stats · anomalies · time-series · text
                       (concurrent.futures.ThreadPoolExecutor, 4 workers)
    P4 ML Chain     →  leaderboard → SHAP explainability
    P5 Reporting    →  cleaning · charts · PDF
    P6 Agentic Q&A  →  brief · RAG · LLM agent (deferred by default)

Every parallel branch is wrapped in pipeline._safe_call() so a single
exception becomes {"available": false, "error": "..."} instead of sinking
the run. Phase timings (per-task ms) ride along in result["timings_ms"].

SLIDE 10  ·  PIPELINE ORCHESTRATOR  (modules/pipeline.py)
────────────────────────────────────────────────────────────────────────────────

run_full_analysis(dataset_id, file_path, original_filename,
                  analysis_mode="standard", skip_ai=False,
                  target_column=None, parallel_workers=4)
                  → JSON-safe result dict

Phase-by-phase, with what runs where.

  P1 — Sequential, structural (≤ 200 ms typical)
       load_dataset                  → pandas DataFrame
       build_profile                 → shape, dtypes, missing,
                                       numeric_summary (df.describe()),
                                       categorical_summary,
                                       df.corr(numeric_only=True), 15-row
                                       preview, memory_usage_mb.
       infer_column_roles            → multi-label dict per column
       summarize_roles               → counts per role
       detect_dataset_signals        → flat boolean dict
       select_analyses               → which downstream phases to run

  P2 — Sequential, quality
       calculate_health_score        → 0..100 + 4 components
       calculate_ml_readiness        → 0..100 + label
       calculate_advanced_indicators → utility score per column

  P3 — ThreadPoolExecutor(max_workers=parallel_workers)
       Submitted as four independent tasks via _safe_call:
         deep_statistics_v2   (run_deep_statistics_v2)
         anomalies_v2         (detect_anomalies_ensemble)
         time_series          (detect_and_analyze_time_series)
         text_profile         (profile_text_columns)
       Per-task elapsed ms → timings_ms["phase3_tasks"].

  P4 — Sequential ML chain (only if target_column is set)
       run_model_leaderboard         → leaderboard rows + winner card
       explain_winner                → SHAP global + per-row stories +
                                       PNG path

  P5 — Sequential reporting
       build_signals                 → human-readable bullets
       create_cleaned_dataset        → cleaned CSV under cleaned/
       generate_charts               → list of {title, type, path}

  P6 — AI report (deferred by default)
       Controlled by env DATALENS_ANALYZE_AI ∈ {0,1}. The dashboard
       hits /api/ai-report on demand instead, keeping /api/analyze fast.

  Failure model
       _safe_call(name, fn) wraps every parallel task. On exception:
         {"available": false, "error": "<ExcType>: <msg>"}
       — the rest of the pipeline keeps going.


────────────────────────────────────────────────────────────────────────────────
SLIDE 11  ·  LOADER INTERNALS  (modules/loader.py)
────────────────────────────────────────────────────────────────────────────────

Why a custom loader.

  •  pandas read_csv defaults choke on real-world files (BOMs, mixed quoting,
     mojibake). DataLens loads anything that landed in uploads/.

Encoding waterfall — pseudo-flow:

    for enc in ("utf-8-sig", "utf-8", "windows-1252", "latin-1"):
        try:
            df = pd.read_csv(path, encoding=enc, low_memory=False)
            break
        except UnicodeDecodeError: continue

  •  utf-8-sig handles the Windows BOM that breaks first-column lookups.
  •  windows-1252 is the silent default for Excel-exported CSVs.
  •  latin-1 is the always-succeeds fallback (every byte is a valid code point).

Format dispatch by suffix:
    .xlsx, .xls          → openpyxl backend (read_excel)
    .json, .jsonl        → pd.read_json (lines=True for jsonl)
    .tsv, .txt           → read_csv with sep="\t"

Memory print-out:
    df.memory_usage(deep=True).sum() / (1024 * 1024)   # MB


────────────────────────────────────────────────────────────────────────────────
SLIDE 12  ·  SECURITY LAYER  (modules/security.py)
────────────────────────────────────────────────────────────────────────────────

Three-line policy.

  1.  Extension allow-list — {csv, tsv, txt, xlsx, xls, json, jsonl}.
      Anything else is rejected at the Flask handler.

  2.  werkzeug.utils.secure_filename — strips path separators, control
      characters, and pre-fixed dots before the file lands in uploads/.

  3.  CSV-injection guard — every cell that begins with a formula trigger
      ('=', '+', '-', '@') is prefixed with a single quote on export,
      neutralising it as a literal string in Excel / Sheets / Numbers.

SLIDE 13  ·  PROFILER  (modules/profiler.py)
────────────────────────────────────────────────────────────────────────────────

build_profile(df) returns a 12-key dictionary, all JSON-safe.

  shape                rows, columns from df.shape
  columns              list(df.columns)
  dtypes               {col: str(dtype) for col in df.columns}
  numeric_columns      df.select_dtypes(include=[np.number]).columns
  categorical_columns  df.select_dtypes(include=["object","category","bool"])
  date_columns         heuristic — see below
  missing_counts       df.isna().sum() per column
  missing_percent      missing / rows × 100, 2 dp
  duplicate_rows       df.duplicated().sum()
  duplicate_percent    rows / total × 100
  memory_usage_mb      df.memory_usage(deep=True).sum() / 1024²
  numeric_summary      df[numeric_cols].describe().T (mean, std, min, q1, q2, q3, max)
  categorical_summary  for each col: nunique + top-10 value_counts
  correlations         df[numeric].corr(numeric_only=True), rounded to 3 dp
  preview              df.head(15) with NaN→None for JSON

Date heuristic:
    sample = df[col].dropna().astype(str).head(25)
    parsed = pd.to_datetime(sample, errors="coerce")
    qualifies if parsed.notna().mean() >= 0.7

This is the conservative date probe used for *flagging*. The deeper
time-series module (Slide 42) re-runs detection with a richer scoring
rule that also considers monotonicity and column-name keywords.

────────────────────────────────────────────────────────────────────────────────
SLIDE 16  ·  HEALTH SCORE  (modules/health_score.py)
────────────────────────────────────────────────────────────────────────────────

Four sub-scores out of 100, then a weighted blend.

  Definitions
    completeness    = 100 − missing_percent
    uniqueness      = 100 − duplicate_percent
    outlier_safety  = 100 − outlier_percent
    consistency     = 100 − (constant_percent + high_cardinality_percent)

  Outlier percent (numeric columns only):
    For each numeric col:
        Q1 = df[col].quantile(0.25)
        Q3 = df[col].quantile(0.75)
        IQR = Q3 − Q1
        flagged = ((col < Q1 − 1.5·IQR) | (col > Q3 + 1.5·IQR)).sum()
    outlier_percent = total_flagged / (n_rows · n_numeric_cols) × 100

  Constant / high-cardinality flags:
    constant   = nunique(dropna=True) <= 1
    high-card  = dtype == object AND nunique > 0.8 · rows

  Overall (with the floor +10 trick that keeps the worst datasets
  from collapsing to single digits):

      Health = 0.30·completeness
             + 0.20·consistency
             + 0.20·uniqueness
             + 0.20·outlier_safety
             + 10

      then clip to [0, 100].

  Labels:
      ≥ 90 Excellent · ≥ 75 Good · ≥ 60 Moderate · ≥ 40 Poor · else Critical


────────────────────────────────────────────────────────────────────────────────
SLIDE 17  ·  ML READINESS  (modules/ml_readiness.py)
────────────────────────────────────────────────────────────────────────────────

Penalty model — start at 100, deduct three penalties.

  missing_penalty   = min(30, missing_percent)
  duplicate_penalty = min(15, duplicate_percent)
  encoding_penalty  = min(20, 2 · n_categorical_cols)

  score = clip(100 − missing_penalty − duplicate_penalty − encoding_penalty, 0, 100)

  Labels:
      ≥ 85 Ready · ≥ 70 Mostly Ready · ≥ 50 Partially Ready · else Not Ready

  Rationale
    •  Missing values cost 1 point each up to 30 — the imputer can absorb
       a third of the table but not more.
    •  Duplicates cost less because dedupe is cheap.
    •  Each categorical column adds 2 points of encoding cost (capped at
       20) because OneHotEncoder explodes width and slows model fits.

SLIDE 18  ·  CLEANER  (modules/cleaner.py)
────────────────────────────────────────────────────────────────────────────────

Conservative auto-clean — does only what is reversible & defensible.

  Steps:
    1.  Numeric NaN → median impute (column-by-column).
    2.  Categorical NaN → mode impute (most_frequent).
    3.  drop_duplicates() — exact-match rows only.
    4.  Sanitise CSV cells before export (CSV-injection guard).

  Returns:

     "before_health":   <full health dict>,
     "after_health":    <full health dict>,
     "rows_dropped":    <int>,
     "values_imputed":  <int>}

  The dashboard renders a "Cleaning Impact" bar chart from
  before_health.overall_score vs after_health.overall_score.



────────────────────────────────────────────────────────────────────────────────
SLIDE 19  ·  DEEP STATISTICS — PER-COLUMN DESCRIPTIVES
────────────────────────────────────────────────────────────────────────────────

Per numeric column, _numeric_column_stats(s) computes:

  count, mean, median, std, min, max          (pandas)
  q1 = s.quantile(0.25)                       q3 = s.quantile(0.75)
  iqr = q3 − q1
  skewness  γ₁  = E[(X − μ)³] / σ³            (pandas Series.skew)
  kurtosis  γ₂  = E[(X − μ)⁴] / σ⁴ − 3        (pandas Series.kurtosis, excess)

Skewness label:
    |γ₁| < 0.5  → Approximately Symmetric
    |γ₁| < 1.0  → Moderately Skewed
    else        → Highly Skewed

Kurtosis label:
    γ₂ > 1     → Heavy-tailed
    γ₂ < −1    → Light-tailed
    else       → Approximately Normal-tailed

Per categorical column, _categorical_column_stats(s) computes:

  unique_count
  cardinality_label  (Constant / Low / Medium / High)
  Shannon entropy:    H = −Σ pᵢ log₂ pᵢ, where pᵢ are category proportions.
  entropy_ratio:      H / log₂(unique_count)        ∈ [0, 1]
  top_values:         {value, count, percent} for the top-10 categories.


────────────────────────────────────────────────────────────────────────────────
SLIDE 20  ·  OUTLIER FLAGS — THREE INDEPENDENT VIEWS
────────────────────────────────────────────────────────────────────────────────

DataLens runs three outlier filters in parallel because each one is right
about a different kind of anomaly.

  IQR (Tukey)
      flagged if  x < Q1 − 1.5·IQR  or  x > Q3 + 1.5·IQR
      Robust to non-normal data; matches the boxplot whiskers.

  Classical z-score
      z  =  (x − μ) / σ
      flagged if  |z| > 3
      Sensitive to distribution shape — fails on heavy-tailed data
      because σ itself is corrupted by the outliers.

  Robust z (MAD)
      median = s.median()
      MAD    = median(|s − median|)
      z*     = (x − median) / (1.4826 · MAD)
      flagged if  |z*| > 3.5
      The 1.4826 constant makes MAD a consistent estimator of σ when
      the underlying distribution is normal.

Returned together as {"iqr": <int>, "z3": <int>, "mad_z": <int>, "n": <int>},
so the dashboard can cross-reference views.


────────────────────────────────────────────────────────────────────────────────
SLIDE 21  ·  NORMALITY TESTS  (scipy.stats)
────────────────────────────────────────────────────────────────────────────────

Three tests run in tandem — each suits a different sample size.

  Shapiro-Wilk         scipy.stats.shapiro(s)
      Best small-sample power; capped at n = 5000.
      H₀: data is normally distributed. Reject at p < 0.05.

  D'Agostino-Pearson   scipy.stats.normaltest(s)
      Combined skew + kurtosis test, requires n ≥ 20.
      Sample to 5000 first when bigger.

  Anderson-Darling     scipy.stats.anderson(s, dist="norm")
      Reports statistic and the 5 % critical value (index 2).

  Verdict logic (deep_statistics_v2.py)
      p_use = shapiro.p if available else dagostino.p
      is_probably_normal = (p_use is not None) and (p_use ≥ 0.05)

  Interpretation strings travel with the result so the React UI can
  show them next to the verdict.


────────────────────────────────────────────────────────────────────────────────
SLIDE 22  ·  DISTRIBUTION FITTING BY AIC
────────────────────────────────────────────────────────────────────────────────

Six candidate distributions, fit via maximum likelihood, ranked by AIC.

  Candidates: norm, lognorm, expon, gamma, weibull_min, beta.

  For each candidate D with k parameters:
      params  = D.fit(sample)        # scipy.stats.<dist>.fit
      log_lik = Σ D.logpdf(x_i, *params)
      AIC     = 2·k − 2·log_lik

  Lowest AIC wins. Leaderboard returned with top-6 entries.

  Edge cases handled
    •  Positive-support dists (lognorm, expon, gamma, weibull_min) are
       skipped if any sample value ≤ 0.
    •  Beta is fit on min-max-rescaled data clipped to (1e-6, 1−1e-6),
       since beta's support is (0, 1).
    •  Samples > 10 000 are randomly subsampled to 10 000 with
       random_state=42 — the AIC ranking is stable beyond that size.
    •  log_lik = ±inf is silently dropped; convergence failures don't
       break the leaderboard.

SLIDE 23  ·  BOOTSTRAP CIs  (scipy.stats.bootstrap)
────────────────────────────────────────────────────────────────────────────────

For every numeric column we report a 95 % CI for both the mean and the
median. The agent can pull these via column_summary().

  Method (preferred): Bias-Corrected and accelerated (BCa)
     accounts for both bias and skewness in the bootstrap distribution.

  res = stats.bootstrap((s,), statistic_fn,
                        n_resamples=999,
                        confidence_level=0.95,
                        method="BCa", random_state=42)

  Fallback: percentile method if BCa fails (e.g. degenerate samples).

────────────────────────────────────────────────────────────────────────────────
SLIDE 24  ·  NUMERIC BIVARIATE — Pearson · Spearman · Kendall
────────────────────────────────────────────────────────────────────────────────

For every pair of numeric columns with at least 10 overlapping non-null
rows, three correlation flavours are reported with p-values.

  Pearson r
      r  =  Σ (xᵢ − x̄)(yᵢ − ȳ)
            ───────────────────
            √Σ(xᵢ − x̄)²  · √Σ(yᵢ − ȳ)²
      Linear, symmetric, requires roughly normal data for inference.

  Spearman ρ
      ρ  =  Pearson r computed on rank(X) and rank(Y).
      Monotone, robust to outliers, no normality assumption.

  Kendall τ
      τ  =  ( #concordant_pairs − #discordant_pairs ) / C(n, 2)
      More robust than Pearson on small samples; conservative p-values.

  Strength labels (DataLens convention):
      |r| ≥ 0.8 Very Strong · ≥ 0.6 Strong · ≥ 0.4 Moderate ·
      ≥ 0.2 Weak · else Very Weak

  Pair budget: max_pairs=20 by default to bound O(n²) over wide tables.


────────────────────────────────────────────────────────────────────────────────
SLIDE 25  ·  CATEGORICAL BIVARIATE — Chi-square + Cramér's V
────────────────────────────────────────────────────────────────────────────────

For pairs of categorical columns with ≤ 30 unique values each:

  contingency = pd.crosstab(a, b)
  chi², p, dof, expected = scipy.stats.chi2_contingency(contingency)
  n   = contingency.values.sum()
  V   = √(  χ²  /  ( n · (min(rows, cols) − 1) )  )

  Strength labels:
      V ≥ 0.5 Strong · ≥ 0.3 Moderate · ≥ 0.1 Weak · else Very Weak

  relationship_likely = (p < 0.05)

  We skip pairs where either column has > 30 unique categories — the
  table explodes and the chi-square statistic becomes unreliable.


────────────────────────────────────────────────────────────────────────────────
SLIDE 26  ·  POINT-BISERIAL · MANN-WHITNEY · KRUSKAL-WALLIS
────────────────────────────────────────────────────────────────────────────────

Specialised bivariate tests when one side is binary or low-card.

  Point-biserial (binary categorical vs numeric)
      Encode {a, b} → {0, 1} and call scipy.stats.pointbiserialr.
      r_pb is mathematically Pearson r on a 0/1 column.
      Reports r, p, strength label, encoding map.

  Mann-Whitney U  (2 groups, non-parametric difference of distributions)
      H₀: P(X > Y) = 0.5
      stat, p = scipy.stats.mannwhitneyu(g1, g2, alternative="two-sided")
      significant = (p < 0.05)

  Kruskal-Wallis H  (3+ groups)
      Generalises Mann-Whitney to multiple samples.
      stat, p = scipy.stats.kruskal(*samples)

  Group filter:
      For each (group_col, numeric_col) pair, only keep groups with ≥ 3
      members; require 2–6 distinct groups so the test is meaningful.


────────────────────────────────────────────────────────────────────────────────
SLIDE 27  ·  ANOMALY ENSEMBLE — DETECTORS 1–4
────────────────────────────────────────────────────────────────────────────────

Pre-processing for every detector:
    1.  Drop columns with ≤ 1 unique value.
    2.  Cap dimensionality at 30 (keep highest-populated columns).
    3.  SimpleImputer(strategy="median").
    4.  StandardScaler() — zero-mean / unit-variance.

  Detector 1 — Isolation Forest  (sklearn.ensemble)
      IsolationForest(n_estimators=200, contamination, random_state=42).
      Anomaly score:
          s(x)  =  2 ^ ( − E[h(x)] / c(n) )
                where E[h(x)] is the average path length for x in 200
                random binary trees and c(n) is the average path length
                for an unsuccessful BST search of n samples.

      In code: raw = − model.score_samples(X)  (negate so big = anomalous)

  Detector 2 — Local Outlier Factor  (sklearn.neighbors)
      n_neighbors = clip(n_rows // 20, 5, 20)
      LOF_k(x)  =  ( Σ_{y∈N_k(x)} lrd(y) / lrd(x) )  /  |N_k(x)|

      In code: raw = − model.negative_outlier_factor_

  Detector 3 — Elliptic Envelope  (sklearn.covariance)
      Robust Gaussian fit; flags rows in the tail of the fitted ellipse.
      raw = − model.score_samples(X).

  Detector 4 — Robust z-score (MAD)  (numpy)
      median  = np.median(X, axis=0)
      mad     = np.median(|X − median|, axis=0)
      z       = |X − median| / (1.4826 · mad)
      raw     = z.mean(axis=1)        # row-level mean of column z's


────────────────────────────────────────────────────────────────────────────────
SLIDE 28  ·  ANOMALY ENSEMBLE — DETECTORS 5–7 (optional)
────────────────────────────────────────────────────────────────────────────────

  Detector 5 — Mahalanobis  (sklearn.covariance.MinCovDet)
      Robust covariance estimate to suppress influential outliers.
      D²(x)  =  (x − μ̂)ᵀ Σ̂⁻¹ (x − μ̂)
      Fall-back path: plain np.cov + np.linalg.pinv with 1e-6 ridge.

  Detector 6 — ECOD  (pyod.models.ecod, lazy import)
      Empirical Cumulative distribution Outlier Detection — non-parametric,
      uses tail probability over each feature's empirical CDF.
      raw = model.decision_scores_.

  Detector 7 — COPOD  (pyod.models.copod, lazy import)
      Copula-based outlier detection — joint tail probability via
      empirical copula. Same shape as ECOD.

  PYOD imports are wrapped in try/except, so missing pyod degrades to
  five detectors instead of failing.


────────────────────────────────────────────────────────────────────────────────
SLIDE 29  ·  ENSEMBLE SCORING & FLAGGING
────────────────────────────────────────────────────────────────────────────────

  Score normalization   _to_unit(scores)
      Min-max scale per detector to [0, 1]; degenerate (constant) scores
      collapse to zeros so a misbehaving detector cannot dominate.

  Stack the per-detector vectors into a (n_rows × n_detectors) matrix:
      score_matrix = np.column_stack(detector_scores.values())

  Ensemble score (mean rank, equal-weighted):
      ensemble = score_matrix.mean(axis=1)

  Summary stats:
      min, mean, median, max, p95, p99 of the ensemble vector.

  Flag rule:
      flagged = (ensemble >= threshold)             # threshold default 0.6
      flagged_count = int(flagged.sum())

  Output:

SLIDE 30  ·  MULTICOLLINEARITY  (modules/multicollinearity.py)
────────────────────────────────────────────────────────────────────────────────

For each numeric feature j, compute VIFⱼ via auxiliary regression.

  Procedure:
      X = df.select_dtypes(include=[np.number])
      X = SimpleImputer(strategy="median").fit_transform(X)
      For each column j:
          y      = X[:, j]
          X_rest = X without column j
          model  = LinearRegression().fit(X_rest, y)
          R²ⱼ    = model.score(X_rest, y)
          VIFⱼ   = 1 / max(1 − R²ⱼ, 1e-9)         (capped at 999)

  Severity buckets:
      VIF ≥ 10  High
      VIF ≥ 5   Medium
      else      Low

  Redundant feature groups
      |corr(Xᵢ, Xⱼ)| ≥ 0.95 marks an edge.
      Connected components of the resulting graph are returned with a
      "keep one representative" recommendation.

SLIDE 32  ·  UNIFIED ML PREPROCESSING  (modules/ml_preprocessing.py)

SLIDE 34  ·  CV SCORING MATRIX
────────────────────────────────────────────────────────────────────────────────

                                     shuffle=True, random_state=42)
    Regression     → KFold(5, shuffle=True, random_state=42)

Scoring dicts (passed to sklearn.cross_validate):
    Classification:
        accuracy            = "accuracy"
        f1_weighted         = "f1_weighted"
        precision_weighted  = "precision_weighted"
        recall_weighted     = "recall_weighted"
        primary             = "f1_weighted"
    Regression:
        r2                  = "r2"
        neg_mae             = "neg_mean_absolute_error"
        neg_rmse            = "neg_root_mean_squared_error"
        primary             = "r2"

Metric formulas (per fold, then averaged):
    Accuracy   =  (TP + TN) / N
    Precision  =  TP / (TP + FP)
    Recall     =  TP / (TP + FN)
    F1         =  2·P·R / (P + R)
    F1_weighted = Σ wᵢ · F1ᵢ over classes (wᵢ = class support / total)
    Brier      =  (1/n) Σ (pᵢ − yᵢ)²        (binary, lower = calibrated)
    R²         =  1 − Σ(yᵢ − ŷᵢ)² / Σ(yᵢ − ȳ)²
    MAE        =  (1/n) Σ |yᵢ − ŷᵢ|
    RMSE       =  √( (1/n) Σ (yᵢ − ŷᵢ)² )

plus _mean / _std for every metric in the dict.

────────────────────────────────────────────────────────────────────────────────
SLIDE 36  ·  SHAP — DERIVATION OF SHAPLEY VALUES
────────────────────────────────────────────────────────────────────────────────

A SHAP value φᵢ(x) measures the contribution of feature i to a single
prediction at point x.

  Definition (Lundberg & Lee 2017, generalising Shapley 1953):

      φᵢ(x)  =   Σ      |S|! ( |F| − |S| − 1 )!
              S ⊆ F\{i}  ─────────────────────────  ·  [ v(S ∪ {i}) − v(S) ]
                                  |F|!

      where  F is the full feature set,
             S is any subset of F not containing i,
             v(S) is the model's expected output conditioning only on the
             features in S.

  Local accuracy property:
      Σᵢ φᵢ(x)  +  E[ ŷ ]   =   ŷ(x)
      i.e. the SHAP values sum exactly to the model's deviation from its
      base prediction. This is what makes SHAP "additive".

  Two desirable properties:
      Missingness:  features with no impact get φ = 0.
      Consistency:  if a feature contributes more in any subset, its φ
                    cannot decrease.


────────────────────────────────────────────────────────────────────────────────
SLIDE 37  ·  SHAP IMPLEMENTATIONS USED
────────────────────────────────────────────────────────────────────────────────

We never compute SHAP from the textbook formula directly — exact
combinatorial SHAP is exponential in the number of features. The shap
library exposes specialised algorithms:

  shap.TreeExplainer
      Polynomial-time exact SHAP for tree ensembles (RF, GB, XGB, LGBM).
      Used when winner_name ∈ {RandomForest…, GradientBoosting…, XGB…, LGBM…}.

  shap.LinearExplainer
      Closed-form SHAP for linear models given a background sample.
      Background = X_train.sample(min(100, len(X_train)), random_state=42).
      Used when winner ∈ {LogisticRegression, Ridge, Lasso, ElasticNet}.

  shap.summary_plot(values, features, feature_names, max_display=15)
      Saves the beeswarm PNG to static/charts/<dataset>_shap_summary.png.

Multiclass aggregation:
    For shap_values returned as (n_samples, n_features, n_classes),
        global_mean_abs = mean( |shap_values|, axis=2 )
    For old-style list-of-arrays (one per class),
        global_mean_abs = mean( [|arr| for arr in shap_values], axis=0 )

Per-row stories:
    row_totals = Σᵢ shap_values[i]
    top_idx    = np.argsort(-row_totals)[:3]
    For each chosen row, sort features by |shap| descending; keep top-5
    contributions. The dashboard renders these as "row N: feature A
    pushed up by 0.43, feature B pushed down by −0.18, …".

One-hot collapse:
    Sum SHAP magnitudes for "<col>_<level>" back to "<col>" before
    showing global rankings — keeps the chart readable.


────────────────────────────────────────────────────────────────────────────────
SLIDE 38  ·  PERMUTATION IMPORTANCE FALLBACK
────────────────────────────────────────────────────────────────────────────────

Always run as a cross-check (and as a sole signal when SHAP fails).

  Method (Breiman 2001, sklearn implementation):
      Train pipeline on X_train, compute baseline score on X_test.
      For each feature j:
          For r in 1..n_repeats:
              Shuffle column j of X_test → X_perm.
              score_r = pipeline.score(X_perm, y_test)
          Δⱼ_r  =  baseline_score  −  score_r
      Importance(j) = mean over r of Δⱼ_r
      Std(j)        = std  over r of Δⱼ_r

  Configuration:
      sklearn.inspection.permutation_importance(
          pipeline, X_test, y_test, n_repeats=5,
          random_state=42, n_jobs=-1, scoring=None)

  Output:
      [{"feature": col, "importance": <float>, "std": <float>}, …]
      sorted by |importance| descending; top-15 surfaced.

SLIDE 40  ·  FEATURE IMPORTANCE  (modules/feature_importance.py)
────────────────────────────────────────────────────────────────────────────────

Two complementary signals.

  Random-Forest impurity importance
      Per split in a RandomForest tree, record the impurity decrease
      weighted by the number of samples reaching that split:
          Δimpurity(s)  =  N_left/N · I(left) + N_right/N · I(right) − I(parent)
      Importance(j)    =  Σ over all splits on feature j of Δimpurity(s)
      Normalised so importances sum to 1 across features.

  Mutual information
      I(X; Y) = Σ_x Σ_y p(x, y) · log[ p(x, y) / ( p(x) · p(y) ) ]
      sklearn.feature_selection.mutual_info_classif (classification)
      sklearn.feature_selection.mutual_info_regression (regression)
      Measures any kind of dependence — linear or non-linear, symmetric.

  Both rankings collapse one-hot expansions back to the original column
  by summing |importance| over the level columns sharing a parent.

SLIDE 42  ·  TIME-SERIES — DATE DETECTION
────────────────────────────────────────────────────────────────────────────────

modules/time_series.detect_date_column(df) scoring rule:

    score = 0.6·parse_rate + 0.3·monotone_score + 0.1·name_is_date_like

  parse_rate
      parsed = pd.to_datetime(col, errors="coerce", format="mixed")
      For numeric columns that look like epochs:
          max(|col|) > 1e18  → unit="ns"
          > 1e15            → unit="us"
          > 1e12            → unit="ms"
          > 1e9             → unit="s"
      parse_rate = parsed.notna().mean()

  monotone_score
      diffs       = parsed.dropna().sort_index().diff().dropna()
      increasing  = (diffs >= 0).mean()
      decreasing  = (diffs <= 0).mean()
      monotone    = max(increasing, decreasing)

  name_is_date_like
      0.1 if "date|time|timestamp|created|updated|datetime|ts|event" in
      lower(col) else 0.0.

  Acceptance threshold:
      parse_rate ≥ 0.7 if name looks date-like, else ≥ 0.95.
      Plus a defensive guard that skips small-integer columns (max < 1e9)
      so a binary "approved" column never gets parsed as ns-since-epoch.


────────────────────────────────────────────────────────────────────────────────
SLIDE 43  ·  FREQUENCY + FFT PERIOD DETECTION
────────────────────────────────────────────────────────────────────────────────

  Inter-arrival summary  _infer_frequency(parsed):
      sorted(parsed.diff()).total_seconds().median()  → label
      Mapping (median Δ in seconds):
          ≤ 1.5     second
          ≤ 90      minute
          ≤ 5400    hour
          ≤ 36·3600 day
          ≤ 9·86400 week
          ≤ 35·86400 month
          ≤ 200·86400 quarter
          else      year

  Plus pd.infer_freq on the first 200 timestamps when the series is
  regular (e.g. "D" / "H" / "MS").

  Period via FFT  _guess_period_via_fft(values, freq_label):
      x          = values − mean(values)
      spectrum   = |np.fft.rfft(x)|
      spectrum[0] = 0                          (kill DC component)
      peak       = np.argmax(spectrum)
      period     = round(len(values) / peak)

      Sanity bounds applied per freq_label so a noisy spectrum cannot
      claim "yearly seasonality" on a 60-row daily series:
          second(5..300) · minute(5..240) · hour(4..168) · day(5..60)
          week(4..26) · month(4..24) · quarter(4..12) · year(3..10).


────────────────────────────────────────────────────────────────────────────────
SLIDE 44  ·  STATIONARITY BATTERY  (statsmodels)
────────────────────────────────────────────────────────────────────────────────

Two tests — opposite null hypotheses — combined into a 4-way verdict.

  ADF  (Augmented Dickey-Fuller)
      H₀: series has a unit root (non-stationary)
      from statsmodels.tsa.stattools import adfuller
      adf_stat, adf_p, *_ = adfuller(s, autolag="AIC")
      reject H₀ at p < 0.05 → stationary.

  KPSS  (Kwiatkowski-Phillips-Schmidt-Shin)
      H₀: series is stationary around a deterministic trend
      from statsmodels.tsa.stattools import kpss
      kpss_stat, kpss_p, _, _ = kpss(s, regression="c", nlags="auto")
      fail to reject at p > 0.05 → stationary.

  Combined verdict:
      ADF stationary  & KPSS stationary    → "stationary"
      ADF non-stat.   & KPSS non-stat.     → "non-stationary"
      ADF stationary  & KPSS non-stat.     → "trend-stationary
                                              (consider differencing once)"
      ADF non-stat.   & KPSS stationary    → "difference-stationary"
      else                                 → "inconclusive"

  Sample size guard: skipped when n < 30.


────────────────────────────────────────────────────────────────────────────────
SLIDE 45  ·  STL DECOMPOSITION  (statsmodels.tsa.seasonal)
────────────────────────────────────────────────────────────────────────────────

We use statsmodels.tsa.seasonal.STL(s, period=p, robust=True).fit().

  Outputs:  trend (T), seasonal (S), residual (R) arrays.

  Strength of trend / seasonality (Hyndman & Athanasopoulos 2018):

      F_T  =  max( 0,  1  −  Var(R) / Var(T + R) )
      F_S  =  max( 0,  1  −  Var(R) / Var(S + R) )

  Both ∈ [0, 1]. Larger values mean a clearer trend (F_T) or seasonality
  (F_S) component vs noise.

  Compact previews exposed to the frontend:
      trend_preview, seasonal_preview, residual_preview = last 50 values.
      trend_summary = {first, last, delta} (so the dashboard can render
      an "up by Δ over the period" headline).

  Skipped if  period < 2  or  n < 2·period + 4.


────────────────────────────────────────────────────────────────────────────────
SLIDE 46  ·  ACF / PACF
────────────────────────────────────────────────────────────────────────────────

Both up to lag = min(40, n // 5).

  Autocorrelation
      ρ(k) = Cov(yₜ, yₜ₋ₖ) / Var(yₜ)
      from statsmodels.tsa.stattools import acf
      acf(s, nlags=max_lag, fft=True)
      FFT-based for speed.

  Partial autocorrelation
      pacf(k) is the correlation between yₜ and yₜ₋ₖ after removing the
      effects of intermediate lags via Yule-Walker / OLS.
      from statsmodels.tsa.stattools import pacf
      pacf(s, nlags=max_lag).

  Both are returned as floats so the dashboard can stem-plot them with
  significance bands at ± 1.96/√n.

SLIDE 47  ·  HOLT-WINTERS vs NAIVE BASELINE
────────────────────────────────────────────────────────────────────────────────

Recursive equations (additive trend + additive seasonality):

      ℓ_t  =  α (y_t − s_{t−m})  +  (1 − α)( ℓ_{t−1} + b_{t−1} )
      b_t  =  β ( ℓ_t − ℓ_{t−1} )  +  (1 − β) b_{t−1}
      s_t  =  γ ( y_t − ℓ_{t−1} − b_{t−1} ) + (1 − γ) s_{t−m}
      ŷ_{t+h}  =  ℓ_t + h · b_t + s_{t + h − m}

Implementation:
    from statsmodels.tsa.holtwinters import ExponentialSmoothing
    ExponentialSmoothing(train,
                         trend="add", seasonal="add" if period else None,
                         seasonal_periods=period,
                         initialization_method="estimated"
                        ).fit(optimized=True)

Validation:
    horizon = clip(period or 12, 6, len(s) // 4)
    train   = s.iloc[: n − horizon]
    test    = s.iloc[n − horizon :]

    naive_forecast = pd.Series([train.iloc[-1]] * horizon, index=test.index)

    For each model: MAE = mean |y − ŷ| · RMSE = √mean( (y − ŷ)² ).

    The dashboard renders four series on one chart: actual, train,
    Holt-Winters forecast, naive forecast.

SLIDE 50  ·  DRIFT — PSI (NUMERIC + CATEGORICAL)
────────────────────────────────────────────────────────────────────────────────

The Population Stability Index quantifies distribution shift between a
reference window R and a current window C.

  Bucketing:
      Numeric: edges from 10 quantiles of the reference,
               edges[0] = −∞, edges[-1] = +∞ to capture cur extremes.
      Categorical: bin per category. Pad with 1e-6 to avoid log(0).

  Bin proportions:
      ref_props = histogram(ref, edges) / |ref|
      cur_props = histogram(cur, edges) / |cur|

  PSI:
      PSI  =  Σ_b  ( cur_props[b] − ref_props[b] ) · ln( cur_props[b] / ref_props[b] )

  Severity buckets:
      < 0.10  stable   ·  < 0.25  minor
      < 0.50  moderate ·  ≥ 0.50  severe

  Numeric float coerce
      Reference and current arrays are explicitly cast to float64 before
      np.quantile — newer numpy refuses to subtract bool arrays inside
      np.quantile, which broke v2 on bool columns. Fixed in v3.

SLIDE 51  ·  DRIFT — KS · CHI-SQUARE · SEVERITY ROLLUP
────────────────────────────────────────────────────────────────────────────────

Kolmogorov-Smirnov two-sample
    stat, p = scipy.stats.ks_2samp(ref_arr, cur_arr)
    KS = max_x | F_ref(x) − F_cur(x) |          (max gap in empirical CDFs)
    flag if p < 0.01.

Numeric column extras:
    z_shift  =  (cur_mean − ref_mean) / pooled_std       (effect size)
    histogram preview (21 edges) so the frontend can twin-bar overlay
        without recomputing the bins.

Categorical drift:
    chi2_stat, chi2_p, dof, _ = stats.chi2_contingency(
        np.array([[ref_count[c] for c in top_K], [cur_count[c] for c in top_K]]))
    flag if chi2_p < 0.01.
    Track new_categories (only in cur) and missing_categories (only in ref).

Verdict rollup:
    severe > 0   → "severe"
    moderate > 0 → "moderate"
    minor > 0    → "minor"
    else         → "stable"

        Sort by parsed date, split into older / newer halves so the same
        comparison engine works on a single uploaded file.

SLIDE 63  ·  LIMITATIONS
────────────────────────────────────────────────────────────────────────────────

What DataLens does NOT do well today.

  •  Default hyperparameters — leaderboard is a baseline, not state-of-art.
  •  Drift compares two halves of one upload; no persistent baseline.
  •  In-memory pipeline; degrades > 1 M rows.
  •  Associational only; no causal inference.
  •  English-centric NLP (NLTK stopwords, English seed lexicon for sentiment).
  •  LLM agent has no pandas-recall yet, so questions outside the brief
     fall back to RAG.
  •  No real-time / streaming support.
  •  Ollama Cloud free-tier only (gpt-oss:120b); larger models gated by
     subscription.
